# Gustav OS - STATUS

Sidst opdateret: 2026-05-26 (Fase 7 led 3 kodet)

## Hvor er vi
Fase 7 led 3 (cron) er KODET, men ikke live før migrations + deploy + env. Webhook fra led 2 ligger på `/api/telegram`. Cron ligger på `/api/cron/actions`, `/api/cron/morning`, `/api/cron/evening` og `/api/cron/patterns`. Alle cron-routes kræver `Authorization: Bearer <CRON_SECRET>` og bruger DB-lock via `cron_locks`, så overlappende invocations ikke udfører samme job dobbelt. `vercel.json` er sat konservativt med daglige schedules, så Vercel Hobby ikke fejler deploy. Hvis kalender-actions skal udføres få minutter efter veto-deadline, skal `/api/cron/actions` rammes hyppigere via Vercel Pro eller ekstern scheduler. Næste er led 4: Vercel deploy, env, Supabase redirect URLs, migrations og webhook-aktivering.

## Noter / faldgruber
- VIGTIGT: Claude Code-shellen har en TOM `ANTHROPIC_API_KEY` der skygger for `.env.local`. Kør scripts som `node scripts/x.mjs` (bruger `load-env.mjs`). Kør dev-server som `env -u ANTHROPIC_API_KEY npm run dev` når Anthropic skal virke lokalt.
- npm cache: brug `npm_config_cache=/tmp/gustav-npm-cache` foran npm-installs (root-ejet `~/.npm`). Permanent: `sudo chown -R 501:20 ~/.npm`.
- Deploy senere: skift fra long-polling til webhook på Vercel for altid-online capture. Watch-actions skal også flyttes til en serverless cron eller en vedvarende proces.
- Webhook env: `TELEGRAM_WEBHOOK_SECRET` skal være sat både lokalt og i Vercel. Smoke-test 2026-05-26 viste at den kørende dev-server manglede den, uden at `.env.local` blev læst direkte.
- Webhook idempotens: kør `supabase/migrations/0004_telegram_webhook.sql` før webhook aktiveres. Ellers returnerer `/api/telegram` 500 ved første rigtige update.
- Cron env: `CRON_SECRET` skal være sat i Vercel og lokalt hvis cron-routes skal testes. Vercel sender den automatisk som `Authorization: Bearer <CRON_SECRET>` når env-var findes.
- Cron migration: kør `supabase/migrations/0005_cron.sql` før `/api/cron/actions` eller `scripts/watch-actions.mjs` bruges efter denne ændring. Watcheren skriver nu `actions.processing_started_at`.
- Vercel Cron timezone: schedules i `vercel.json` er UTC. `0 5 * * *` er derfor ca. 07 dansk sommertid og 06 dansk vintertid.
- Vercel Hobby: officielle Cron-limits tillader kun daglige schedules. `vercel.json` er derfor Hobby-safe. Hvis veto-actions skal udføres få minutter efter deadline, brug Vercel Pro eller ekstern scheduler der kalder `/api/cron/actions` hvert 5. minut med `Authorization`-header.
- Proxy: `/api/*` skal forblive ekskluderet i `proxy.ts`. API-routes validerer sig selv. Hvis `/api/telegram` begynder at returnere 307 til `/login`, er matcheren blevet ødelagt.
- Whisper: ~95% nøjagtig på dansk. Råtekst gemmes altid, så intet går tabt.
- Google service account: nøgle ligger på én linje i `.env.local` med tekst-`\n`. Fold ud med `.replace(/\\n/g, '\n')` før brug. Læse-scope (`calendar.readonly`) i `calendar.mjs`, skrive-scope (`calendar.events`) i `calendar-write.mjs` - hold dem adskilt.
- audit_log: gemmer kun terminal-states (`applied`/`vetoed`/`failed`). Forslag (proposed actions) bor kun i `actions`-tabellen. Hvis Supabase under setup ikke kender `actions.type` (eller andre kolonner mangler), kør `drop table actions cascade;` og derefter `0002_actions.sql` igen - tabellen er kun forslag, så det er sikkert.
- pgvector ivfflat-index: kræver mere `maintenance_work_mem` end Supabase's default 32MB. Først relevant ved tusinder af chunks. Når du tilføjer det, foranstil med `SET maintenance_work_mem = '128MB';` i samme SQL-blok. Indtil da er sequential scan hurtigt nok.
- PostgREST schema-cache: efter nye funktioner/tabeller skal cachen reloades. Kør `notify pgrst, 'reload schema';` i SQL Editor hvis du får PGRST202 ("Could not find the function...").
- Embed-modellen er `text-embedding-3-small` (1536 dim). Skifter du model, skal `memory_chunks.embedding`-kolonnen recreates med ny dimension OG alle eksisterende rækker re-embeddes. Lås modellen indtil det giver mening.
- Next.js 16 server actions: filer med `'use server'` i toppen må KUN eksportere async funktioner. Konstanter og type-exports skal ligge i separat fil ellers serialiseres de som Server References og dukker som `undefined` op på klienten.
- Next.js 16 file convention: `middleware.ts` er deprecated, brug `proxy.ts` med eksporteret funktion `proxy()`. Default runtime er Node.js (ikke Edge). Codemod findes: `npx @next/codemod@canary middleware-to-proxy .`.
- Server actions er IKKE separate routes i proxy-chain-pipelinen; de POST'er til den route hvor de bor. En matcher-ændring eller refaktor der flytter en server action kan silently fjerne proxy-coverage. Derfor verificerer `askAction` selv at brugeren er logget ind (`getServerSupabase` + `getUser` + whitelist). Gør det samme i alle fremtidige server actions.
- Auth: brug `getUser()` (round-trip til Supabase) eller `getClaims()` (lokal JWT-validering) til autorisationsbeslutninger. `getSession()` læser kun fra cookies og må IKKE bruges til at gate noget (en angriber kan crafte en cookie).
- Supabase magic link rate limit: Free tier sender 3-4 mails pr. time fra deres SMTP. For test-loops: log ind én gang, brug "Log ud"-knappen, log ind igen - cookies invalideres uden ny mail.
- Service_role-klienten (`lib/supabase.ts`) er nu mærket med `import 'server-only'`. Hvis nogen importerer den til et client component knækker buildet med det samme. Brug `getServerSupabase()` fra `lib/supabase-server.ts` til alt der har med en bruger at gøre.
